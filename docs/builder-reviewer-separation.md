# 写实现 ≠ 审查(Builder–Reviewer Separation)

## 为什么

LLM 对自己产出的代码存在系统性"自我确认偏置":同一上下文里自己写自己审,缺陷检出率显著偏低,
且实现者倾向于为通过而降低标准。参考工程与业界实践一致要求**实现与审查上下文分离**。

## 规则

1. 同一轮任务:builder(或任何写实现的上下文)不得担任 `reviewer` / `visual-reviewer` / `acceptance-checker`。
2. **禁止自评**:任何"完成/通过"结论必须出自与实现者不同的上下文。
3. **一个修复一个核验**:reviewer 打回的问题逐个修,每修一个立即独立核验,全过才算闭环;禁止打包修复后只核验一次。
4. 实现者不得为通过测试而降低验收标准或测试口径;对标准有异议 → 停下交用户裁决。
5. 主 Agent 负责综合结论,但必须独立复核改动与证据,不照搬子 Agent 意见。

## 落地方式

- Codex:`.codex/agents/*.toml` 的 `sandbox_mode` 读写分离(read-only 审查者物理不可改文件)。
- 其他工具:生成物中角色提示词同源(.etherkit),人工保证上下文分离(新开会话/新实例)。
